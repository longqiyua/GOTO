# GOTO 产品需求文档

版本：2.1（Page 源整理版）  
更新日期：2026-08-02  
状态：页面与 Android 预览同步基线

## 1. 产品定位

GOTO 是一个本地优先的移动应用启动器。用户只需要记住一条线索，就能通过唯一搜索框找到并启动应用；系统再用快捷索引、模糊匹配、情境排序和本地统计减少下一次操作成本。

核心承诺：**更短的启动路径、更少的注意力占用、可解释的本地智能。**

非目标：GOTO 不做云端搜索、不替用户安装应用、不把不可解释的推荐当作确定结果，也不在 Page 中复制 Engine、Base、Where 的实现。

## 2. 架构边界与权威源

- `GOTO Page/` 是页面、文档和页面级预览的唯一源。
- `GOTO/app/src/main/assets/goto_page/` 是 Android WebView 的同步副本。
- Kotlin 宿主通过既有 Bridge 注入已安装应用；Page 负责展示与交互。
- GOTO Engine 负责召回、匹配与重排；GOTO Base 负责事实、配置和事件；GOTO Where 负责情境解释与展示权重。
- Engine、Base、Where 已定档，本 PRD 不要求也不允许修改其实现。
- Page 中的“SuperGOTO”只是进阶能力的页面级总开关；它不改变 Engine、Base、Where 的边界。开启后展开自适应刷新、元标签索引、模糊匹配、模拟智能与 GOTO Where 智能提醒等既有卡片。
- 设置页将 SuperGOTO 呈现为进阶区域内的独立卡片；卡片本身负责展开/收回既有进阶卡，右上角仅显示带渐变光感的当前状态。

## 3. 核心用户流程

1. 用户点击或聚焦搜索框。
2. 输入名称、拼音、缩写、标签或模糊线索。
3. Engine 返回候选，页面展示命中原因、排序和耗时。
4. Where 在允许时结合时段、前台应用和最近行为调整展示顺序。
5. 用户点击结果，Kotlin 宿主启动目标应用并记录一次本地事件。
6. Base 保存配置与行为，统计页提供反馈；下一次搜索只使用可解释的既有数据。

## 4. 功能需求

### 4.1 搜索与启动（P0）

- 支持中文名、英文名、包名、拼音全拼、拼音首字母、常用缩写和模糊输入。
- 结果必须包含可解释的命中类型；空结果时展示可关闭的建议，不伪造命中。
- 支持标准确认启动和即时启动两种模式。
- 记录搜索、点击、启动成功/失败和耗时；数据只保存在本地。

### 4.2 快捷索引与悬浮入口（P0）

- 用户可以把一段短字符绑定到一个应用或设置项。
- 冲突规则明确显示，并提供覆盖、取消和恢复默认操作。
- 悬浮入口支持单击搜索、双击行为和边缘吸附；系统权限被拒绝时给出可行动提示。

### 4.3 光感模式（P1）

- 根据时间或环境光输入平滑过渡明暗与强调色。
- 光感模式优先申请系统定位权限，以纬度、经度、时区和当前/预览时刻计算日出日落、太阳高度角与方位角，并将方位映射为陶瓷亮面方向。
- 定位被拒绝、超时或不可用时，使用时区对应经度与中纬度模型近似，不阻塞光感模式；用户仍可手动选择时区。
- 过渡必须保持内容可读，不因动画导致按钮位置跳动。
- 支持手动关闭、预览清晨/正午/日落/深夜和降低动态效果。

光感模式的亮面方向由太阳方位角驱动：页面优先通过系统权限获取位置；权限不可用时按时区与中纬度模型估算，不阻塞使用。标准模式仍保持简约线条材质，陶瓷/玉石质感只属于光感模式。

### 4.4 文档与手机预览联动（P1）

- 文档中的“联动预览”按钮可以打开左侧对应页面，并将目标卡片滚动到可见位置。
- Engine 文档可直接执行一次只读查询；PRD 与架构文档能跳转到真实设置、统计或搜索状态。
- 每次联动提供短暂高亮和状态反馈，不改变用户已有设置，除非用户明确操作。

### 4.5 GOTO Music（P1）

- 目录底部按钮首次点击即可准备并播放默认演示曲目。
- 播放/暂停必须与隐藏播放器和完整 Music 文档页共享同一状态机。
- 播放列表中的每个文件路径必须对应 `GOTO Page/music/` 中的真实文件；加载失败时显示可理解的状态。
- 离开 Music 文档页不停止已开始的音频，返回时恢复播放器状态。

## 5. 页面体验要求

- 不做大幅改版，保持左右分栏、左侧手机预览、右侧文档阅读的现有结构。
- 统一控制、卡片、面板和手机壳的圆角层级；通过间距和留白建立层次。
- 光感模式使用连续的颜色、阴影、边框和背景光过渡；支持 `prefers-reduced-motion`。
- 文档目录保留固定底部 Music 入口，目录滚动不能被文档切换重置。
- 加载失败必须有回退：文档回退 bundle、播放器回退 bundle、页面错误提示。

## 6. 约束与验收

### 工程约束

- 不修改 GOTO Engine、GOTO Base、GOTO Where 实现。
- 页面改动先落在 `GOTO Page/`，生成 `Document/document-bundle.js`，再同步 Android asset。
- 不改变 Kotlin Bridge 的字段语义；页面只消费已有注入协议。

### 5.1 Page 与 Base / Where 的边界

首页“最近”和“常用”卡片消费统计页写入的真实应用启动数据，并通过 Base 已有的应用身份与图标信息解析展示；Page 只负责排序、布局和状态反馈，不复制或改写 Base 的事实层。统计页的“智能统计应用排名”在样本不足以形成时间段聚类时，展示同一统计快照的“当前统计”兜底排名，禁止生成演示数据或重复应用。

GOTO Where 的提醒在 Android 宿主中由 `GOTOAndroidBridgeNative.sendNotification()` 转交现有 Where 通知投递适配器，沿用系统权限、通知渠道、去重和冷却策略；GitHub Pages 预览则回退到 Web Notifications API 与页面内反馈。打开 GOTO Where 或光感模式时，权限申请必须由系统对话框发起。

## 7. 发布说明

### 7.1 文档源与 note-to-show

文档区域采用“文件夹源文件 → `note-to-show` → 右侧正文”的单向链路。编辑者只修改 `GOTO Page/Document/` 中的 Markdown/HTML；`document-bundle.js` 由脚本重新生成，供静态托管与 Android WebView 做离线回退。页面首屏可以沿用既有渲染结果，但实时更新由 `note-to-show` 监听当前文件并刷新右侧内容，刷新失败不得清空上一份可读内容。

`note-to-show` 是独立模块，采用 Apache License 2.0（SPDX：`Apache-2.0`）。它只负责文档呈现、样式契约和本地更新，不复制或改写 GOTO Engine、GOTO Base、GOTO Where 的算法与数据契约。

### 7.2 GOTO Prethink 与边界适配

搜索在进入既有协调器前可经过独立 `GOTO Prethink` 层。Prethink 不清理或改写用户输入，而是依据键盘邻位、字符交换、重复/缺失字符、拼音与英文转换、搜索—点击历史和当前手机应用清单，生成最多 3–5 个带 `query / confidence / source / editCost / explanation` 的并行候选；原始查询始终保留且权重最高。每个候选进入同一个 Engine，由 Engine 统一竞争并拥有最终解释权；低于最低置信度的候选丢弃，重复路径按最高分减去第二路径的有限奖励合并。Prethink 不改动 GOTO Engine、GOTO Base、GOTO Where 三个冻结组件，模型接入点对用户隐藏并必须可解释。异形屏适配覆盖安全区、平板、横屏、折叠屏和 flip 形态，窄屏下收起文档栏但保留手机预览与可访问操作，不改变桌面三栏信息结构。

GitHub Pages 使用 `site` 分支承载构建后的页面，发布目录为 `GOTO Page/`。任何发布前修改都应先在 Page 源预览，再运行 bundle 检查和 Android asset 同步。历史 PRD 保留作为背景资料，不与本版本的权威约束冲突。
