## 唯一的产品主体

GOTO 的主体不是设置页、卡片或统计图，而是首页搜索框。

1. 默认状态只显示搜索框，保持低注意力占用。
2. 第一次点击后，搜索框自然上移并向下延展，出现问候和预测应用。
3. 开始输入后，问候卡片隐藏，延展高度随结果数量变化。
4. 清空输入后恢复问候状态；再点击空白区域，才回到默认状态。
5. 点击结果或预测应用后直接启动，并在底部轻量提示“已打开 XX”。

## 四条搜索路径

### 1. 直接匹配

当名称、拼音、英文或缩写明确命中时，结果优先出现。精确、前缀、包含三类信号按确定性排序。

### 2. 模糊匹配

用户输错字母时，系统比较字符重叠、邻位交换和键盘距离。邻位交换风险最高，因此只有存在字符重叠才参与，并保持最低优先级，防止候选失控。

### 3. 元标签索引

当用户记得“用途”而不是名称，例如“打车”“支付”“文档”，本地标签把意图映射到应用。名称匹配仍然优先，标签只补充候选。

### 4. 快捷索引

用户可以用声明式句子建立规则：**我想要打开 XX 应用，通过输入 XX 字符。** 一个字符只有一条规则时默认大小写兼容；相似规则发生冲突时才区分大小写。

<div class="doc-logic-callout"><b>排序原则</b><span>确定性先于智能；用户明确选择先于系统推断；行为数据只能重排已有候选，不能凭空制造结果。</span></div>

## 为什么还需要进阶能力

基础搜索解决“能不能找到”，进阶能力解决“能不能更稳定地找到”。GOTO 的进阶层不是单一开关，而是一套从输入解析、候选重排到行为学习的完整链路。下面把后台正在运行的所有机制按“输入侧”和“后台侧”两组完整列出，每一项都可以在本地存储和引擎源码中找到对应实现。

### 输入侧 · 多维度匹配

用户一次输入会被同时投射到多个匹配维度，所有维度独立计算、最后按确定性合并，不会互相覆盖。

**精确层（确定性最高）**

- **名称精确**：应用中文名、英文名、缩写（如 `wx` / `dd` / `zfb`）与输入完全相等时直接命中。
- **拼音全拼**：拼音全字符串精确匹配，例如 `weixin` 命中“微信”。
- **应用 ID**：内部 `byAppId` 索引直接定位，确保插件注入的应用也能被精确召回。

**前缀层**

- **名称前缀**：从首位开始的子串匹配，例如“微”命中“微信”。
- **拼音前缀**：拼音首部匹配，例如 `wei` 命中“微信”。

**首字母层**

- **拼音首字母缩写（initials）**：取拼音每位首字母，索引长度 1–4。例如 `wx` 命中“微信”、`zfb` 命中“支付宝”。索引在 `buildSearchIndex` 时按 1/2/3/4 长度分别建表，保证短输入也能精确召回。

**字符层**

- **字符索引（byChar）**：对名称、拼音、英文名中出现过的每个字符建立倒排，支持任意单字符模糊召回。
- **T9 数字键盘**：输入 `942` 可命中 `w`/`x`/`i` 对应的应用，键位映射沿用经典 `2→abc, 3→def, …, 9→wxyz`。

**意图层（记得用途但不记得名称时）**

- **元标签索引（metaSearch）**：本地分类词库覆盖 20 个分类（通讯、办公、浏览器、视频、音乐、购物、支付金融、地图出行、拍照影像、阅读资讯、游戏、开发、系统工具、输入法、智能家居、网盘云盘、翻译、教育学习、健康运动、跑腿快递），每个分类携带应用列表与关键词集合。用户输入“打车”“支付”“文档”时，元标签把意图映射到对应应用，但只补充候选，不抢占名称匹配的位置。
- **意图同义词（11 类）**：`SEND / CONSUME / CONTACT / TRAVEL / BUY / WORK / SEARCH / OPEN / INSTALL / HEALTH / LEARN`，每类携带 15–20 个中文触发词，用于推断用户动作意图并标注 `intentLabel`。

**模糊层（输错时兜底）**

- **Levenshtein 编辑距离**：动态规划计算输入与候选的编辑距离，用于拼写纠错。
- **邻位交换（Swap）**：检测相邻字符被颠倒的情况（如 `wexin` ↔ `weixin`）。因为 Swap 风险最高，规则要求**必须存在字符重叠才参与**，并保持最低优先级，防止候选失控。
- **键盘距离（QWERTY 物理距离）**：基于键盘物理位置的相邻键判定，`q` 与 `w` 距离近、`q` 与 `p` 距离远，用于评估“按错键”的概率。
- **字符重叠率**：输入与候选的字符集合交集比例，作为模糊层是否启用的门槛。

**语义层（可选扩展）**

- **L1 核心同义词**：内置高频同义词映射，启动即用。
- **L2 同义词词林分片**：22 个拼音首字母分片，按需懒加载。
- **L3 词向量**：基于本地训练的轻量向量相似度，仅在 L1/L2 未命中时兜底。语义模块整体可禁用，删除 `semantic/` 目录即完全关闭。

<div class="doc-logic-callout"><b>合并原则</b><span>所有维度独立计算后按确定性合并：精确 > 前缀 > 首字母 > 字符 > 意图 > 模糊 > 语义。行为数据只能重排已有候选，不能凭空制造结果。</span></div>

### 后台侧 · 学习与维护

这一组机制在后台持续运行，但全部可解释、可追溯、可清理。

**刷新与节流**

- **自适应刷新（HAC 算法）**：根据近 5 次有效输入测量调节刷新间隔；样本不足统一使用 200 ms；单次偏差超过 50% 的异常值会被过滤。算法包含 T1 防抖、T2 节流、犹豫补偿延迟 Δ_hesitate（在 Gaussian 键位距离衰减或 Swap 纠错触发时叠加）、高置信度直通（高匹配度快速输入跳过自适应刷新直接执行）四个调节项。
- **搜索周期识别**：连续快速启动被视为同一搜索周期内的误操作，与自适应刷新校正使用同一套逻辑，避免短时间内的重复统计。

**候选重排（Boost）**

- **时段画像 Boost**：根据当前小时与历史启动频率加权（`hourly × 18 + allTime × 4`，上限 90），早上常开的新闻、晚上常开的视频会自然前移。
- **权重 Boost**：基于用户历史选择权重（`weight − 0.5` 映射到 ±110 区间），权重越高的候选加分越多。
- **启动次数 Boost**：累计启动次数越多，候选越靠前。
- **安装状态 Boost**：已安装应用优先于未安装。

**行为学习**

- **Chain-of-Action Routing**：记录“从 A 应用启动后下一步常打开 B”的行为链，用于生成快捷气泡预测。链式边总数上限 500，每个起点最多保留 20 条边，权重低于 1 的边会被清理。
- **跨查询全局偏好**：用户对某个应用的总体偏好跨所有查询共享，不受单一查询上下文影响。
- **相似查询权重传递**：前 2 字符相同或字符重叠率 ≥ 0.5 的查询视为相似，权重按 0.2 比例传递，让相近的搜索意图共享学习成果。
- **微观上下文（Micro-Context）**：在 v1.5 中扩展，结合更短时间窗口内的行为序列做细粒度预测。

**反馈与纠错**

- **负反馈权重调整**：用户点击候选后，排在被点击项之前的候选会被降权（`ignored` 计数 +1）；某个候选累计被忽略 3 次后权重直接清零。
- **权重时间衰减**：30 天半衰期，权重向 0.5 收敛，下限 0.35，避免历史权重完全消失也避免旧偏好永久主导。
- **屏蔽标记**：用户长按候选可加入屏蔽列表，默认屏蔽 3 天，期间不再出现在该查询的候选中。屏蔽列表上限 200 条，超出按最早设置时间淘汰。
- **自愈机制**：当系统检测到用户连续跳过排名第一的候选、直接选择排名靠后的应用时，会自动把排名第一的候选加入屏蔽并提升被选应用权重，避免重复推荐错误结果。
- **点击延迟 EMA**：指数移动平均记录用户从输入到点击的延迟，用于调节模拟智能的置信度——延迟越短说明候选越准确。

**统计与画像**

- **统计系统**：只在用户长按激活后记录，且只统计从 GOTO 内完成的应用启动。激活前所有数值保持 0；激活后但尚无样本时图表显示 `null`，不填充演示数据。
- **小时分桶热力图**：按 24 小时分桶统计启动次数，用于时段画像。
- **智能统计应用启动排名**：通过分析 GOTO 使用间隔切分使用时段（允许时段重叠），统计 24 小时内启动频率最高的前 5 个应用，与小时热力图互补。
- **四类可解释指标**：首选命中率、搜索转启动率、行为链稳定度、时段画像完整度。每一项都可追溯到本地行为记录。
- **物理硬件动作推荐**：v1.5 扩展，基于当前情境推荐硬件层面的快捷动作（如打开手电、调节亮度）。

**视觉与环境**

- **光感模式**：按位置、时区与一天中的时刻改变明暗、色温、玻璃透明度和光源方向。它是一套独立材质体验，不是简单深色主题；关闭后恢复浅色或深色主题，不影响功能位置与卡片层级。
- **增强模拟智能**：v1.5 扩展，在原有四类指标基础上增加更细粒度的情境推断，但仍只显示轻量建议，不替用户做决定。
- **超级语音**：规划中的"拓展"类预览功能。目标不是替代键盘，而是把语音交互从"点击 → 录入 → 关闭"的三段式闭环里抽出来，提供**对话式、非抢占注意力**的快捷操作方式；当前仅占位，不请求麦克风权限。详见"功能 / 超级语音"独立页。

**引擎自主维护**

- **链式边剪枝**：链式边总数超过 500 或单节点超过 20 条时按权重剪掉低价值边。
- **记忆记录过期**：记忆记录最长保留 90 天、最多 220 条，超出自动清理。
- **过期屏蔽清理**：每次查询屏蔽标记时自动清理过期项。

**性能层（v3.2 新增）**

- **搜索结果 LRU 缓存**：32 条查询结果缓存，5 分钟 TTL，基于数据集指纹（长度 + 首项 + 末项）兜底失效；在索引重建、用户选择反馈、屏蔽标记变更、自愈触发、权重写入时主动清空，保证一致性。
- **状态内存缓存**：10 个 localStorage 状态键（记忆、待索引、统计、权重、链式、负反馈、屏蔽标记等）首次读取后缓存在内存，写入时同步更新，避免每次 getter 都做 `getItem + JSON.parse`。
- **插件层实例缓存**：`EngineComponent` 实例根据数据集引用与长度复用，避免每次查询重建；反馈通道采用批量写入（5 条阈值或 2 秒延迟），减少 localStorage 操作次数。

**扩展层**

- **GOTO-Engine 插件 API**：版本化宿主 `GOTOPlugin`，支持第三方插件注册 `beforeSearch / afterSearch / beforeRender / onFeedback / onError` 五个 hook，权限作用域覆盖 `search.read / search.rerank / search.options / render.modify / context.write / feedback.send / feedback.receive / engine.maintain`。
- **反馈通道**：`GOTOFeedback` 提供本地缓冲（200 条上限）+ 批量写入 + 可选远端上报，插件可通过 `onFeedback` hook 接收纠正/建议/错误信号。
- **独立分发**：`GOTO-ENGINE/` 顶层文件夹是引擎的独立副本，可作为插件开发的权威入口；引擎源码主仓位于 `AppIndex/GOTO-Engine/`，GithubPages 镜像位于 `GithubPages/GOTO-Engine/`，三处保持算法一致。

## 数据如何形成闭环

搜索本身不会被算作应用启动。只有用户点击候选并从 GOTO 发起启动，才写入本地启动记录。统计激活之前，所有统计数值保持 0；激活后但尚无样本时，图表显示 `null`。

模拟智能使用四类可解释指标：首选命中率、搜索转启动率、行为链稳定度和时段画像完整度。每一项都可追溯到本地行为记录，不填充演示数据。

## 视觉为什么克制

标准模式使用正统包豪斯秩序：黑白灰层级、唯一强调色、清楚的边框和稳定网格。光感模式承担材质展示：高透毛玻璃、随日照变化的色温和有限炫光。两者共享相同布局与交互，不因视觉模式改变卡片宽度、层级或功能位置。
